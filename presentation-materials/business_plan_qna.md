# เอกสารบันทึกข้อมูลแผนธุรกิจและข้อมูลการเตรียมนำเสนอโครงการ (Pitching & Business Plan Notes)
## โครงการ MaCheck — ระบบตู้ยาและตรวจสอบความปลอดภัยสำหรับผู้สูงอายุ (ฉบับอัปเดตตรงตามระบบจริง)

เอกสารนี้ได้รับการปรับปรุงข้อมูลให้ตรงกับสถาปัตยกรรมระบบจริงของโปรเจกต์ MaCheck (แอปฝั่งคุณตา, ระบบหลังบ้าน Express, คลาวด์ Supabase, และแผงควบคุมแพทย์ Doctor Portal) เพื่อใช้เป็นแนวทางตอบคำถามคณะกรรมการได้อย่างแม่นยำและเป็นมืออาชีพที่สุดครับ

## 💡 2. คุณค่าหลักและการจัดลำดับความสำคัญของฟีเจอร์ (Value Proposition - ข้อ 3.4)
> **โจทย์วิเคราะห์:** ฟีเจอร์ใดในแอปพลิเคชันที่เป็นตัวขับเคลื่อนคุณค่าที่โดดเด่นและสำคัญที่สุดต่อชีวิตของผู้ใช้

* **ฟีเจอร์หลัก (Value Proposition):** **ระบบวิเคราะห์และคัดกรองความปลอดภัยยาแบบสองระดับ (Dual-Layer Safety Validation Ecosystem)**
* **เหตุผลความสำคัญ:**
  ปัญหาปฏิกิริยาระหว่างยาหรือ **"ยาตีกัน" (Drug-Drug Interactions)** และข้อห้ามใช้ในกลุ่มโรคเฉพาะบุคคล (เช่น การใช้ยาไอบูโพรเฟนในผู้ป่วยโรคไต) เป็นสาเหตุหลักที่ทำให้อวัยวะผู้สูงอายุล้มเหลวเฉียบพลันและเป็นอันตรายถึงแก่ชีวิต โครงการนี้จึงไม่ได้เน้นเพียงแค่การเตือนเวลากินยา แต่เน้น **"การประเมินความปลอดภัยเชิงป้องกันก่อนยาเข้าสู่ร่างกายคุณตา"** โดยแบ่งการปกป้องออกเป็น 2 ระดับอย่างเป็นระบบ:

### การปกป้องระดับที่ 1: ด่านหน้าฝั่งผู้สูงอายุ (Patient-Side Offline-First Scanner & Local Matrix)
* **กลไกการทำงาน:** ระบบทำงานแบบ **Offline-First 100%** ผ่านคลังข้อมูลยาในเครื่อง เมื่อคุณตาจำลองกล้องถ่ายภาพซองยา ระบบจะประมวลผลความเสี่ยงทันทีและรายงานผลผ่านรหัสสีสัญญาณไฟจราจร 3 สี (แดง/เหลือง/เขียว) พร้อมสรุปความสัมพันธ์ของยาทั้งตู้ใน **ตารางวิเคราะห์ความสัมพันธ์ยา 2 มิติ (Interaction Matrix Grid)** ป้องกันการทานยาชนกันแม้คุณตาจะอาศัยอยู่ในพื้นที่ห่างไกลหรือไม่มีอินเทอร์เน็ต

### การปกป้องระดับที่ 2: ด่านหลังฝั่งบุคลากรทางการแพทย์ (Doctor-Side Web Dashboard & Gemini AI Clinical Summary)
* **กลไกการทำงาน:** เมื่อคุณตามาพบแพทย์ แพทย์สามารถเปิด **Doctor Portal (แผงควบคุมสำหรับแพทย์)** ผ่านปุ่มจำเพาะในแอป เพื่อดึงข้อมูลประวัติสุขภาพจากฐานข้อมูลคลาวด์ Supabase มาวิเคราะห์ในตาราง Matrix 2 มิติ และใช้พลังของโมเดล **Gemini 1.5 Flash** ในการวิเคราะห์และสรุปประวัติสุขภาพทั้งหมด (โรคประจำตัว, ยาที่แพ้, ยาในตู้, และประวัติการสแกน) ออกมาเป็นรายงานสรุปทางคลินิก (Clinical Evaluation Report) ในเสี้ยววินาที ช่วยให้แพทย์จ่ายยาตัวใหม่ได้อย่างรวดเร็วและปลอดภัยที่สุด

## 🛡️ 3. กลยุทธ์การป้องกันคู่แข่ง (Defensive Moat - ข้อ 4.5)
> **โจทย์วิเคราะห์:** การรับมือและสร้างปราการความได้เปรียบทางธุรกิจเมื่อถูกลอกเลียนแบบระบบการซิงค์ออฟไลน์หรือระบบสะกิดระยะไกล

1. **Two-Sided Platform Lock-in (การสร้างเครือข่ายความสัมพันธ์สองฝั่ง):**
   แอปคลังยาทั่วไปทำหน้าที่เพียงจดบันทึกให้ผู้ป่วยดูฝ่ายเดียว (Single-sided App) แต่ MaCheck ทำงานเชื่อมโยงแบบ **สองฝั่ง (Double-sided Ecosystem)** คือฝั่งแอปคุณตาบนมือถือและฝั่ง **Doctor Portal** ของแพทย์ผ่านระบบคลาวด์ ทำให้เกิด "เวิร์กโฟลว์การรักษาร่วมกัน" ซึ่งช่วยล็อกสิทธิ์และเพิ่มความผูกพันในการใช้งานระบบของคลินิกและโรงพยาบาลท้องถิ่น ยิ่งใช้งานยิ่งย้ายระบบยาก
2. **Proprietary localized Database (ฐานข้อมูลท้องถิ่นที่เฉพาะตัวสูง):**
   ฐานข้อมูลยาออฟไลน์จำเพาะ (`local_ai_db.ts`) ของเรา ประกอบไปด้วยยารักษา โรคประจำตัว และข้อมูลจำเพาะถิ่น เช่น **ของแสลงและสมุนไพรท้องถิ่นไทย (Local Drug-Food Clash)** ซึ่งเก็บสะสมข้อมูลจำเพาะจากแพทย์และเภสัชกรไทยวิชาชีพอย่างต่อเนื่อง ทำให้แม่นยำต่อพฤติกรรมการกินและวิถีชีวิตผู้สูงอายุไทยมากกว่าฐานข้อมูลสำเร็จรูปทั่วไป
3. **Emotional Value Integration (การลดช่องว่างทางดิจิทัลด้วยเสียงและอวตาร):**
   การออกแบบอินเตอร์เฟสแบบ **Senior UI** ร่วมกับเสียงพูดนำทาง "หลานรัก AI" (ผ่าน *Expo Speech*) ที่ปรับความเร็วให้ช้าลงและโต้ตอบอย่างอ่อนโยน ช่วยสร้างคุณค่าทางจิตใจ (Emotional Value) และลดช่องว่างทางเทคโนโลยีของผู้สูงอายุ ทำให้ผู้สูงอายุเกิดความไว้เนื้อเชื่อใจและไม่ยอมเปลี่ยนไปใช้แอปคู่แข่งตัวอื่น

## 💻 4. เหตุผลเชิงเทคนิคในการเลือกใช้ระบบ (Technology Selection - ข้อ 5.2)
> **โจทย์วิเคราะห์:** เหตุผลและสถาปัตยกรรมระบบที่ใช้ React Native Expo, Zustand, Supabase, และ Express Backend + Gemini 1.5 Flash

ระบบของเราถูกสร้างขึ้นภายใต้สถาปัตยกรรมแบบ **Hybrid Offline-First Sync Architecture** ซึ่งตอบโจทย์การทำงานทั้งความเร็ว ความเสถียร และความปลอดภัยทางการแพทย์:

* **React Native Expo (Mobile Frontend):**
  ช่วยให้เขียนโค้ดภาษาเดียวแต่สร้างแอปพลิเคชันได้ทั้งระบบ iOS และ Android อย่างรวดเร็ว มีระบบจัดการเสียงพากย์ภาษาไทย (*expo-speech*) และระบบเชื่อมต่อไปยังเบราว์เซอร์ของแพทย์ (*Linking API*)
* **Zustand & AsyncStorage (Lightweight Offline State Management):**
  เป็นระบบจัดการข้อมูลตัวเครื่องที่มีประสิทธิภาพสูงและประหยัดแรม เหมาะกับโทรศัพท์ผู้สูงอายุ ช่วยให้ระบบสามารถประเมินผลยาในตู้แบบ **Offline-First** ได้เสถียร 100% เมื่อไม่มีสัญญาณอินเทอร์เน็ต โดยทำการดึงข้อมูลมาแคชเก็บไว้ล่วงหน้า
* **Express Backend Node.js (REST API Server):**
  ทำหน้าที่เป็นเกตเวย์กลางหลังบ้าน จัดการระบบตรรกะความปลอดภัยที่ซับซ้อน, ระบบแจ้งเตือนสะกิดระยะไกล (`pending_nudge`), และทำหน้าที่เชื่อมโยงแอปกับระบบประมวลผลสมองกล **Gemini AI SDK** เพื่อดึงข้อมูลประวัติสุขภาพผู้ป่วยและเขียนรายงานสรุปด้วยโมเดล **Gemini 1.5 Flash** ส่งไปยังแพทย์อย่างปลอดภัย
* **Supabase Database (Real-time Cloud Database):**
  ทำหน้าที่จัดเก็บฐานข้อมูลผู้ป่วย (Profiles, Meds, Logs) แยกจากเครื่องของคุณตาลงฐานข้อมูล PostgreSQL และรองรับการทำ *Real-time Database Subscription* เพื่อซิงค์ข้อมูลสัญญาณสะกิด (Cloud Nudge) จากหน้าจอลูกหลานไปยังเครื่องคุณตาได้ในทันทีที่มีสัญญาณอินเทอร์เน็ต
